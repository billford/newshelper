# ADR-001: NewsHelper — Beyond-the-Headline Daily News Digest

Status: Accepted — v1 shipped 2026-07-21
Date: 2026-07-21
Deciders: Billfordx

## Context

Most news aggregators optimize for clickable headlines, not understanding.
NewsHelper is a static site that, each day, surfaces a small number of top
headlines (starting with 6) and for each one provides an AI-generated summary
of the underlying story plus a short list of deeper follow-ups — articles
and, notably, books — that most aggregators never suggest.

Constraints from discussion:

- Static site, no server/database.
- Hosted on GitHub Pages now, with a planned move to Cloudflare Pages later.
- Headline data from free RSS feeds (Google Trends, Google News, plus other
  outlet feeds), not a paid news API.
- Summaries and book/article recommendations generated by a local model
  running on "wanderlust" (a home-network machine running Ollama/LM Studio),
  not the Claude API — zero ongoing inference cost.
- Book/article suggestions from the local model are still verified against a
  real books API (Open Library primary, Google Books fallback) before
  publishing, since local models carry the same hallucination risk as any
  LLM.
- Rebuilds once daily via a scheduled job.
- Python build script (fits pylint/bandit/unit-test requirement directly, no
  Node toolchain).

## Decision

Build a Python static-site generator that runs once a day on wanderlust
itself, via cron — not GitHub Actions. This is a direct consequence of the
local-model choice: wanderlust is a home-LAN machine, and a cloud-hosted
GitHub Actions runner can't reach a LAN-only Ollama/LM Studio endpoint
without exposing it to the internet (tunnel/VPN), which is unnecessary
attack surface for what should be a private box. Running the whole pipeline
locally avoids that entirely — the model never needs to be reachable from
outside the network.

1. **Fetch** — pull headline candidates from several RSS feeds.
2. **Rank** — score by cross-feed frequency to approximate "trending," pick
   the top 6. Deterministic/algorithmic, not model-based — see Trade-off
   Analysis.
3. **Enrich** — for each headline, call the local model (via Ollama/LM
   Studio's local API) to produce a plain-language summary of the broader
   story and to suggest related books and articles. Book suggestions are
   then checked against Open Library (fallback: Google Books) — unverified
   titles are dropped, not published.
4. **Render** — turn the day's 6 stories into static HTML (Jinja2
   templates), no client-side JS required.
5. **Publish** — the build script commits the generated `dist/` output and
   git pushes to the GitHub Pages branch from wanderlust itself (needs a
   deploy key or PAT stored locally on that machine, not in GitHub Actions
   secrets).

## Options Considered

### Headline sourcing: RSS feed set

Confirmed: Google Trends + Google News. Notes on the broader set, since
several of these are unofficial/undocumented endpoints:

| Feed | Status | Notes |
|---|---|---|
| Google Trends daily trending searches | `https://trends.google.com/trending/rss` — appears active | Gives trending search terms, not full articles. Good signal for "what's hot," not a story source by itself. |
| Google News top headlines | `https://news.google.com/rss?hl=en-US&gl=US&ceid=US:en` — active | Also supports per-topic feeds (`/rss/headlines/section/topic/TECHNOLOGY`) and keyword search feeds (`/rss/search?q=...`), capped at 100 items per feed. Undocumented by Google, could change without notice. |
| BBC News | Documented RSS feeds (e.g. bbc.com/news/.../rss.xml variants) | Reasonably stable, editorially distinct from Google. |
| NPR | `feeds.npr.org/1001/rss.xml` (and topic-specific feed IDs) | Confirmed active. |
| AP News | No confirmed direct public RSS as of this check | Some aggregator sites republish AP content via their own feeds; not the same as an AP-hosted feed. Verify before relying on it. |
| Reuters | Mixed signal | Reuters discontinued its public RSS feeds a few years back per prior knowledge. Needs a direct check before building anything on it. |

**Decision:** start with Google News (multiple topic feeds) + Google Trends +
BBC + NPR. Treat AP/Reuters as "nice to add later, verify first."

### Book/article recommendation sourcing

Decided: the local model handles summarization/framing, and book suggestions
are verified against a real books API before publishing — Open Library
(primary) or Google Books (fallback) — rather than trusting the model's
memory for titles, authors, and links. This avoids the main hallucination
risk here: an LLM asked to recommend books from memory can invent
plausible-sounding titles, authors, or ISBNs, or misattribute a real book's
contents. Flow: the model suggests a topic/angle for a follow-up book, then
the build script queries the books API to confirm the title actually exists
and pulls a real link/cover/author — if no match is found, that suggestion
is dropped rather than published unverified.

### AI inference: local model on wanderlust vs. Claude API

Decided: fully replace Claude with a local model for summaries and
book/article framing, run via Ollama or LM Studio on wanderlust. Zero
marginal API cost for daily builds.

Model candidates (verify current availability at build time via
`ollama.com/library`): Llama 3.1/3.3 (8B), Qwen2.5 (7B–14B), Mistral
(7B/Small). Sizing depends on wanderlust's actual RAM/VRAM — an 8B model in
Q4 quantization needs roughly 5-6GB of memory; a 14B model roughly 9-10GB.
Since this is a once-a-day batch job, a larger model than would be used for
interactive chat is reasonable.

Quality note: local models in the 7-14B range are noticeably weaker than
Claude at nuanced summarization and are more, not less, prone to inventing
plausible-sounding details — which is exactly why the books-API verification
step matters, and why the headline ranking/dedup logic (step 2) stays plain
code rather than asking the model to judge "are these the same story."

### Visual design

Decided: an old-newspaper editorial style, hand-built in plain HTML/CSS (no
framework/JS build step needed).

- Warm off-white page background, dark charcoal body text, one muted accent
  color (amber/brown) — not a typical SaaS-blue palette.
- Serif display font for headlines (e.g. Lora, Source Serif 4, or Playfair
  Display — exact pick TBD), sans-serif for meta text (source, date,
  category badge).
- One lead story gets full treatment: category badge + sources line, large
  serif headline, plain-language summary paragraph, then a "go deeper" list
  mixing article links and book recommendations (book entries show a
  "verified via Open Library" credit line).
- The other five headlines render as a condensed one-line list below the
  lead story, not as five more full cards.

### Hosting: GitHub Pages → Cloudflare Pages

No conflict — a plain static `dist/` output directory works on both. Moving
later just means pointing Cloudflare Pages at the same repo/branch; no
rebuild logic changes needed if GitHub Pages-specific config (e.g.
Jekyll-only features) is avoided.

## Trade-off Analysis

- RSS-only sourcing is free and legally low-risk but noisier than a curated
  headlines API — the ranking/dedup logic (deciding "these 4 feed entries
  are the same story") is the hardest part of this project, harder than the
  AI summarization step.
- Verifying book recommendations against a books API adds one extra network
  call per suggestion but removes the main hallucination risk in this
  project — worth the small complexity cost, more important now that a
  smaller local model is doing the suggesting.
- Local inference on wanderlust brings ongoing cost to ~$0, at the price of
  lower summary quality than Claude and a hard dependency on that machine
  being on and reachable at build time — no local model, no daily build,
  unless a fallback path is added later.
- Running the build on wanderlust instead of GitHub Actions means the
  pipeline's uptime is tied to home network/power, not GitHub's
  infrastructure.

## Consequences

- Wanderlust needs Ollama or LM Studio installed and serving a chosen model
  before any build work starts.
- Wanderlust needs a cron job (or systemd timer) instead of a GitHub Actions
  schedule, plus a git deploy key/PAT stored locally to push the built site.
- No Claude API key or GitHub Actions secret needed for the AI step.
- Cross-feed story-matching logic (e.g. fuzzy title/entity match) is the
  main open engineering problem, not the AI calls.
- Python build script ships with unit tests and passes pylint/bandit from
  the start — RSS-fetching, ranking, and rendering are separate testable
  functions rather than one script. Testing the "local model" step uses a
  mocked Ollama/LM Studio response, not live calls to wanderlust, so tests
  stay deterministic and don't require the machine to be on.
- AP/Reuters feed status needs a direct check before relying on either.
